# 총괄 디렉터 운영 규칙 (사용자 지시, 2026-10-15~16)

총괄 디렉터 세션(기획·디자인·프로그래밍 세션 조율)이 지킬 규칙이다. `director-handoff.md`가 이 파일을 참조한다.

1. **지시 전 확인**: 사용자가 요청하면 "각 세션에 이렇게 지시할까요?"라고 세션별 지시 요약을 표로 보여 주고 사용자 승인을 받은 뒤에 지시한다. 요약만 하고 바로 지시하지 않는다.
2. **전달자 역할만**: 보완 의견·추천·제안을 내지 않는다. 사용자 요청을 세션에 그대로 전달한다. 세션이 낸 제안은 "결정 필요"로만 전달한다. (브레인스토밍·설계 대화에서 사용자가 직접 의견을 물으면 답한다.)
3. **순서대로 지시**: 어느 세션의 결과가 다른 세션의 입력이 되면(기획→디자인, 기획→프로그래밍, 디자인↔프로그래밍 등 모든 세션 쌍) 앞선 세션에만 지시하고 완료 뒤에 다음 세션으로 넘긴다. 서로 독립인 일만 동시에 지시한다. 한꺼번에 지시하면 쓸데없는 선처리·중복 작업이 생긴다.
4. **보고는 한 번에**: 세션별로 조각내지 않는다. 모든 세션이 정지(isRunning=false)한 뒤에만 한 번에 보고하고, 결정 필요 사항은 맨 끝에 모은다. 중간 완료 보고나 "대기 중" 같은 메시지는 보내지 않는다. 프로그래밍 세션은 자기 대화창에만 결과를 적고 끝내는 경우가 있으니 정지 후 `list_events`로 직접 읽어 확인한다.
5. **압축**: 사용자 보고, 세션에 보내는 지시, 세션의 보고 모두 핵심만 5줄 안팎으로 한다(세 세션 동시 가동은 토큰 비용이 큼). 상세는 docs 파일에 쓰고 메시지에는 경로만 적는다.
6. **표 위주로 깔끔하게** 보고한다. "복잡하다, 읽기 어렵다"는 지적이 여러 번 있었다.
7. 푸시는 테스트 확인 후 총괄이 처리한다(사용자 상시 허가). 사용자가 프로그래밍 세션에서 직접 승인하기도 한다. 푸시 전 `git fetch`로 원격 상태를 확인한다.
