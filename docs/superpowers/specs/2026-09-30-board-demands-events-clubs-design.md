# 이사진 요구 선택 / 이벤트 확대 / 구단 DB 확장 설계

날짜: 2026-09-30 · 상태: 사용자 검토 대기

## 목표

같은 구단, 같은 요구, 같은 이벤트가 반복돼서 식상해지는 걸 줄인다.
**리그 안의 힘 구도(강/중/약)는 고정**하고, **구단 색채·요구 조건·이벤트는 런마다 다르게** 나오게 한다.

## 현재 상태 (근거)

- 시작 구단은 `data/clubs.mjs`의 `CLUBS` 4개 고정. 승격 오퍼(`buildTierClubOffers`)는 20개 이름 어간을 모든 리그에서 재사용하고 접미사만 바꾼다.
- 이벤트는 `data/run-preseason-event.mjs`에서 **런 시작 시 1번만** 굴린다(후보 4개 중 하나, 그중 하나는 "없음"). 2시즌부터는 안 뜬다.
- 시즌 목표는 리그 기준선 + 구단 기대치(`expectationModifier`)이고, 초과 달성 보상은 `55c390b`에서 도입됨(`boardGoalPoints`/`boardReward`).

## 1. 구단 DB 확장

**구도(고정):** 리그마다 정확히 20팀 = 강팀 5 · 중위권 10 · 약팀 5. 5개 리그 × 20 = 구단 100개, 전부 고유 이름(리그 간 중복 없음).

| 유형 | 이사진 기대치(목표 승점 가감) | 시작 자금 배율(기본) |
|---|---|---|
| 강팀 | +5 | ×1.3 |
| 중위권 | 0 | ×1.0 |
| 약팀 | −5 | ×0.8 |

**색채(구단마다 다름):** 유형과 별개로 구단마다 색채 1개를 붙인다. 색채 약 10종(예: 유스 육성형, 재벌 투자형, 수비 축구, 공격 축구, 역습 전문, 베테랑 중심, 해외파 중심, 지역 밀착형, 재정 위기형, 신흥 강호). 색채가 정하는 것:
- 강점/약점 문구(시작 화면 표시)
- 시작 자금 배율 보정(유형 배율에 곱함)
- **요구 카드 풀과 이벤트 가중치 편향**(예: 유스 육성형은 "유스 기용" 요구가 잘 나오고 "유스 골든 제너레이션" 이벤트 가중치가 높다)

**노출:** 시작 화면과 승격 오퍼는 강팀 1 · 중위권 1 · 약팀 1 + 무작위 1(시작 화면 4개, 승격 오퍼 3개는 강/중/약 각 1)을 뽑는다. 유형은 항상 고정 비율로 보이지만 구단은 매번 달라진다. 리그 순위표의 상대 구단(`buildLeagueRivals`)도 같은 20팀 로스터를 쓴다.

**이름:** 리그별 전용 어간 20개 × 접미사(리그 격에 맞게). 100개 전부 손으로 확정해 `data/clubs.mjs`에 둔다(런타임 조합 아님).

## 2. 이사진 요구 선택 (선택형 보너스)

- **시점:** 구단을 고른 직후(커리어 시작 화면 앞)와 **매 시즌 브리핑 팝업**.
- **방식:** 요구 카드 3장(쉬움/보통/어려움)을 보여주고 1장을 고른다. 안 고르고 넘길 수도 있다(보너스 없음).
- **보상:** 달성 시 다음 시즌 지급액의 일정 비율(쉬움 +5% / 보통 +10% / 어려움 +20%). 못 해도 페널티 없음. 시즌 결산 화면에 판정, 다음 시즌 브리핑 팝업에 보상 표시(기존 `pendingBoardReview` 흐름에 합친다).
- **카드 풀(초기 8~10종):** 유스 출신 N명 선발 / 평균 나이 N세 이하 / 영입에 자금 N% 이상 쓰지 않기 / 특정 포지션 최고 OVR 유지 / 겨울 시장 거래 0건 / 전반기 승점 N 이상 / 선발 라인업에 같은 대륙 N명 이상 / 시즌 종료 시 적응도 N 이상. 판정은 시즌 종료 시점의 상태(`squad`, 이력 카운터)만 보고 하는 순수 함수 `check(state)`로 둔다.
- **편향:** 뽑는 3장은 구단 색채로 가중한다.

## 3. 이벤트 확대

- **빈도:** 매 시즌 여름 시작에 70% 확률로 1개, 겨울 시장 진입에 30% 확률로 1개. 같은 이벤트가 다시 나와도 된다(중복 방지 없음). 확률은 상수 2개(`EVENT_CHANCE_SUMMER`, `EVENT_CHANCE_WINTER`)로 두고 플레이 후 조절한다.
- **풀:** 기존 7종 유지(승격 전용 2종은 승격 때만) + 신규 5~7종: 라이벌의 에이스 영입 시도 / 부상자 속출(벤치 약화) / 언론 압박(적응도 변동) / 은퇴 앞둔 레전드 영입 기회 / 감독 자리 위협 / 스폰서 계약 조건부 보너스 등. 구체 수치는 구현 계획에서 확정한다.
- **표시:** 기존 이벤트 팝업(`eventmodal`)을 재사용한다.

## 데이터 흐름 / 영향 범위

- `data/clubs.mjs`: 구단 100개 + 색채 표로 재구성. `CLUBS`의 기존 4개는 색채 표로 흡수.
- 새 `data/board-demands.mjs`: 카드 정의 + 판정 함수. 새 `data/season-events.mjs`: 이벤트 정의 + 굴림(기존 `run-preseason-event.mjs`를 대체).
- `ui/app.mjs`: 시작 화면(구단 선택) 뒤에 요구 선택 단계 추가, 시즌 브리핑 팝업에 요구 선택 추가, 이벤트 굴림 호출 위치 이동. 세이브에 `boardDemand`(선택 카드 id·시작 시점 카운터) 추가, `local-save.mjs`에 기본값.
- 밸런스: 요구 보상은 자금만 준다(승점에 직접 영향 없음). 구단 유형 기대치는 기존 ±5 그대로라 `tune-ladder`는 변하지 않는다. 구현 후에도 재측정한다.

## 테스트

- 요구 카드 `check` 순수 함수별 통과/실패 각 1개.
- 로스터: 리그마다 20팀, 5/10/5 비율, 이름 전역 유일.
- 시작/승격 오퍼가 유형 비율대로 뽑히는지.
- 이벤트 굴림이 확률 상수를 따르는지(rng 주입).

## 범위 밖 (이번에 안 함)

- 요구 카드 미달 페널티(선택형으로 결정됨).
- 겨울 시장 요구 카드 재선택.
- 색채가 게임 규칙에 직접 주는 효과는 시작 자금 배율과 풀 편향까지. 그 이상(전용 시작 선수 등)은 추후.

## 구현 순서 제안

1. 이벤트 확대(가장 작고 체감이 큼) → 2. 요구 선택 → 3. 구단 DB(이름 100개 작성이 가장 큼).
