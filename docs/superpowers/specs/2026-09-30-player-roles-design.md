# 선수 특수 태그 재설계: 역할 슬롯 + 장단점

날짜: 2026-09-30 · 상태: 사용자 검토 대기

## 목표

특수 태그가 "있으면 OVR이 조금 붙는" 패시브라서 결정이 없고 영향이 미비했다.
**역할 슬롯에 세워야 발동(A)** 하고 **강한 태그는 대가가 있는(B)** 구조로 바꿔서
"누구를 사서 어디에 세울지, 대가를 감수할지"가 결정 대상이 되게 한다.
태그 보유 카드 비율은 30% → **20%**로 낮추고, 대신 태그 하나의 영향을 키운다.

## 현재 (근거)

- `SPECIAL_TRAITS` 6종(`engine/constants.mjs`), 효과는 `engine/ovr.mjs`(`computeSelfTraitBonus`, `computeTeamTraitBonuses`, `computeContinentSynergyBonus`)가 선수 개인/라인업/벤치 조건만 보고 자동 적용.
- 생성은 `data/generate-player.mjs`에서 `rng() < 0.3`, 이벤트(`data/season-events.mjs`)가 성골 유스·베테랑 리더를 직접 만든다.
- UI는 전술 탭 팀 케미 패널(`renderChemistryPanel`)에 "보유 N명"만 표시.

## 1. 역할 슬롯 3개

| 슬롯 | 자리 | 들어갈 수 있는 태그 |
|---|---|---|
| 주장 | 선발 11명 중 1명 | 베테랑 리더, 폴리글롯 |
| 에이스 | 선발 11명 중 1명 | 성골 유스, 지역 영웅, 저니맨, 스타 기질(신규) |
| 조커 | 벤치 5명 중 1명 | 슈퍼 서브 |

- 태그 효과는 **그 태그의 슬롯에 배정된 선수**에게서만 발동한다. 슬롯 밖이면 태그는 표시만 되고 효과 없음.
- 한 슬롯에는 선수 1명. 같은 슬롯 후보가 둘 이상이면 하나만 발동(→ 선택).
- **기본은 자동 배정**: 슬롯 후보 중 효과가 가장 큰 선수를 자동으로 넣는다. 유저가 바꾸면 `currentState.roleOverrides = { captain?, ace?, joker? }`(선수 id)로 고정, "초기화"로 되돌림.
- 후보가 없으면 슬롯은 "비어 있음".

## 2. 태그별 효과와 대가 (초안 수치)

| 태그 | 슬롯 | 효과(슬롯에 있을 때) | 대가 |
|---|---|---|---|
| 베테랑 리더 | 주장 | 선발 23세 이하 전원 OVR +3, 거래당 적응도 하락 −1 완화 | 재계약비 ×1.5 |
| 폴리글롯 | 주장 | 그 대륙 케미 요구 인원 2명 감면(최소 2명) | 없음 |
| 성골 유스 | 에이스 | 본인 OVR +8 | 없음(유스 출신 한정 태그) |
| 지역 영웅 | 에이스 | 본인 OVR: 잔류 시즌당 +4(상한 +12) | 방출·판매 시 팀 적응도 −8(팬 반발) |
| 저니맨 | 에이스 | 본인 OVR +8(영입한 시즌 한정) | 재계약해도 최대 1년 |
| 스타 기질(신규) | 에이스 | 본인 OVR +10 | 영입가 ×1.5, 재계약비 ×1.5 |
| 슈퍼 서브 | 조커 | 선발 전원 OVR +1 | 조커 슬롯이라 선발 출전 불가(벤치 고정) |

에이스 후보가 4종이라 "누굴 에이스로 세울지"가 진짜 선택이 된다.

## 3. 카드 생성

- `rng() < 0.3` → **`0.2`**. 후보 풀은 `SPECIAL_TRAITS` 7종(스타 기질 추가). 베테랑 리더는 33세 이상만.
- 영입가 ×1.5(스타 기질)는 생성 시 `price`에 반영해서 상점·재계약 계산이 그대로 동작하게 한다. 재계약 ×1.5는 `renewalCost` 호출부에서 태그별 배수를 곱한다.
- 이벤트가 만드는 카드(성골 유스 무료 영입, 은퇴 앞둔 레전드)는 그대로 두되 수치만 새 값을 따른다.

## 4. 엔진 변경

- `computePlayerFinalOVR(player, lineup, bench, boostedTagId, roles = null)`. `roles = { captain, ace, joker }`(선수 id). `null`이면 `autoRoles(lineup, bench)`로 자동 배정한 결과를 쓴다.
- 새 순수 함수 `autoRoles(lineup, bench)`(`engine/roles.mjs`): 슬롯별 후보(태그가 맞는 선수)를 모아 "그 태그 효과가 라인업에 가져오는 OVR 합"이 가장 큰 선수를 고른다.
- `computeSelfTraitBonus`/`computeTeamTraitBonuses`/`computeContinentSynergyBonus`(폴리글롯 부분)는 "슬롯에 배정됐는가"를 인자로 받는다. 배정 안 된 태그는 0.
- 팀 전력 계산에 쓰는 모든 경로(`computeAverageOVR`, `computeTeamPower`, `runHalfSeason`)는 `roles`를 그대로 흘려 보낸다(선택 인자, 기본 자동).
- `computePlayerBonusBreakdown`이 역할 기여도 출처로 보여준다(`kind: 'role'`).

## 5. UI 변경

- 전술 탭 피치 아래에 **역할 칩 3개**: `주장 · 김OO ▾` 형태. 누르면 후보 목록(태그 보유 선수, 조커는 벤치)이 뜨고 선택하면 고정. 비어 있으면 "후보 없음".
- 팀 케미 패널의 특수 태그 배지는 "발동 / 대기(슬롯 경쟁에서 밀림)" 상태와 대가 문구를 함께 보여준다.
- 영입 카드의 태그 칩: `[에이스] 스타 기질` 처럼 슬롯을 앞에 붙이고, 칩을 누르면 효과 + 대가를 설명한다.
- 선수단 행: 대가가 있는 태그는 툴팁으로 대가를 알린다.

## 6. 데이터 / 저장

- `SPECIAL_TRAITS`에 `starPower` 추가, `TRAIT_ROLE = { veteranLeader: 'captain', ... }` 상수, `TRAIT_DOWNSIDE` 텍스트/배수 상수.
- 세이브: `roleOverrides ??= {}` 기본값. 구세이브 선수의 옛 태그는 그대로 유효(슬롯 규칙만 새로 적용).

## 밸런스

- 태그는 슬롯 제약으로 동시에 발동하는 수가 최대 3개(에이스/주장/조커 각 1)라 총 보너스에 상한이 생긴다. `tune-ladder`의 봇은 태그를 안 보므로 리그 튜닝은 그대로다(전 구간 재측정은 하되 변동은 없어야 함).
- 태그 보유 비율 20%, 에이스 후보 수를 고려해 기대 발동 슬롯 수를 시뮬 없이 손으로 계산: 스쿼드 20명 중 태그 보유 4명, 그중 슬롯이 다른 종류로 겹치지 않으면 3슬롯 발동 가능.

## 테스트

- `autoRoles`: 슬롯별 최적 배정, 같은 슬롯 경쟁 시 큰 쪽 선택, 후보 없음.
- 슬롯 밖 태그는 보너스 0, 슬롯 안은 새 수치(각 태그 1개씩).
- 수동 `roles`가 자동을 덮어쓴다.
- 대가: 스타 기질 가격 ×1.5, 베테랑 리더 재계약 ×1.5, 저니맨 재계약 상한 1년, 지역 영웅 방출 시 적응도 −8.
- 카드 생성 확률 20%(rng 주입).

## 범위 밖

- 역할별 전용 신규 태그를 더 늘리는 것(스타 기질 1종만 추가).
- 역할 슬롯 수 늘리기(3개 고정).
- 태그 간 조합 시너지(대안 D).
