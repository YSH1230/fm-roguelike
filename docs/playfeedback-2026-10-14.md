## 1. 판매 중 선수 규칙 (사용자 확정)

### 1.1 규칙
| 항목 | 규칙 |
|---|---|
| 등록 직후 | **화면 이동 없음.** `listForSale`의 `currentState.tab = 'draft'`·`draftSub = 'sell'` 자동 전환을 제거. 토스트(배너) "OOO 판매 등록 — 오퍼는 영입 탭의 판매에서 확인", 판매 탭 배지(오퍼 N건)는 유지 |
| 선발·벤치 | 판매 중 선수는 **선발·벤치에서 자동 제외**. 라인업은 대체 선수로 자동 재편(`pickBestXI`가 판매 중 선수를 풀에서 뺌). 수동 배치(manualOverrides·benchOverrides)에 있던 선수는 등록 때 그 칸을 비움 |
| 정원 N/22 | 판매 중 선수도 **정원에 포함** |
| 선수단 탭 | 판매 중 선수는 선발·벤치·예비 구역에서 빠져 맨 아래 "판매 중 N명" 구역(접힘 가능). 행: 이름·별·오퍼 N건·가장 빠른 만료 기한·[등록 취소] |
| 전력 | 전술 탭·팀 전력·시즌 전망·시뮬 모두 판매 중 선수를 **빼고** 계산(전력 손실이 생김) |
| 등록 취소 | 구역의 [등록 취소] 한 번으로 복귀. **복귀는 자동 배치**(pickBestXI가 별 기준으로 다시 계산, 예전 수동 배치는 복원하지 않음) |
| 수락 | 이미 라인업에서 빠져 있으므로 **공백 경고 없음.** 선수단에서 제거, 정원 −1, 거래 조직력 벌칙(충성형 추가 −2는 유지), 자금 +N |
| 만료·시장 종료 | 오퍼 전부 만료 또는 시장 종료 시 **조직력 −1**(`SALE_EXPIRE_CHEMISTRY`), 선수는 선수단으로 복귀(자동 배치), 알림 "OOO이(가) 선수단으로 돌아왔어요(조직력 −1)" |
| 시장 마지막 주 확인 | 판매 중 선수가 남은 채로 "다음 주"(전반기·후반기 시작)를 누르면 확인 줄 "판매 중 N명이 선수단으로 돌아와요(조직력 −N)" |
| 방출 확인 창 | 판매 중 선수의 [방출]·[판매 등록]은 비활성(먼저 등록 취소). 정원 초과 자동 방출(`capOverflow`)은 판매 중 선수를 제외(다른 후보가 없을 때만 포함) |
| 이중 등록 | 이미 판매 중이면 [판매 등록됨] 비활성(현행) |
| 이벤트·주장 | 판매 중 선수는 출전 요구 이벤트 후보와 자동 주장 후보에서 제외. 임명 주장은 유지(팔리면 이탈 규칙) |
| 오퍼 없는 선수 | "아직 오퍼가 없어요"로 구역에 남고 주마다 재시도(현행) |

### 1.2 등록 확인 문구(전력 손실 고지)
선수단 행 인라인 확인 줄(`confirmRelease`)을 아래로 교체한다.
- 기본: `OOO을(를) 판매 등록하면 선발·벤치에서 빠져요. 오퍼를 받는 동안 전력이 줄 수 있어요. [등록] [취소]`
- 선발인 선수: `…선발에서 빠져요. 대신 ○○○(포지션)이(가) 들어가요(전력 −N.N). [등록] [취소]` — 대체 선수와 전력 변화는 `pickBestXI` 미리보기로 계산(전력 변화는 별 차이가 아니라 팀 전력 숫자가 아닌 "전력 약간 감소/비슷/크게 감소" 3단계 문구로 충분: 변화 < 0.5 비슷, 0.5~2 약간, 2 이상 크게).
- 같은 포지션 대체가 없을 때: `…같은 포지션 선수가 없어 무명 보충 선수가 들어가요.`
- 판매 탭의 등록 안내 줄(`.note`)도 새 규칙으로 고친다: "판매 중인 선수는 선발·벤치에서 빠져요. 오퍼가 모두 만료되면 조직력이 조금 떨어지고 선수단으로 돌아와요."

### 1.3 수정 파일
`ui/app.mjs`(`listForSale`, `listPlayer`, `pickBestXI`와 그 호출처 전체(풀에서 판매 중 제외), `resolveListedSales`, `endListing`, `acceptSaleOffer`, `capOverflow`, 선수단 탭 렌더 `renderMarket`, `confirmRelease` 문구, 시장 마지막 주 "다음 주" 확인 `next-week-btn`), `ui/style.css`("판매 중" 구역, D), `tools/sim-v3.mjs`(판매 중 선수 제외 없음: 봇은 판매 즉시 처리하므로 변경 불필요).
- 구현 힌트: 판매 중 id 집합 `listedIds(currentState)`를 하나 만들어 `pickBestXI`의 `pool`에서 제외하면 호출처가 한꺼번에 해결된다. 자동 주장·출전 요구 후보 필터도 같은 함수를 쓴다.

### 1.4 테스트 기준
- 판매 등록 직후 현재 탭 유지(선수단 탭 → 선수단 탭).
- 선발 선수를 등록하면 `pickBestXI` 결과에 그 선수가 없고 정원 표시 N/22는 그대로.
- 등록 취소 후 같은 선수가 별 기준으로 다시 선발에 들어온다.
- 오퍼 수락 후 공백 경고가 뜨지 않는다(라인업이 이미 재편된 상태).
- 시장 종료 때 판매 중 선수는 모두 선수단으로 복귀하고 조직력이 정확히 −(선수 수).
- 판매 중 선수의 방출 버튼이 비활성이고, 정원 초과 자동 방출이 판매 중 선수를 먼저 건드리지 않는다.

## 2. 튜토리얼 개편 (사용자 확정)

### 2.1 규칙
| 항목 | 규칙 |
|---|---|
| 형태 | **샌드박스**: 튜토리얼은 본 게임과 분리된 임시 상태(7절). 끝나면 상태를 폐기하고 구단 만들기부터 **새 본 게임**을 시작 |
| 범위 | 1주차 ~ 전반기 결산(현행 단계 0~15) + 새 마무리 장면 2개 |
| 마지막쯤 추가 | ⓐ **선수단과 인사하는 장면**(전반기 결산 직후, 후반기 시작 전) → ⓑ **라커룸 토크 1회** → "튜토리얼 끝, 본 게임 시작" 안내 |
| 토크 허용 | 라커룸 토크는 **1시즌부터** 허용(임시 감독도 가능). 정식 임명은 **철학 선택만** 담당(`startTalkThen`·`endTalkThen`의 `appointed` 조건 제거) |

### 2.2 선수단 인사 장면 (ⓐ)
- 장면: `showDialogueScene` 재사용(새 종류 `squad`). 라커룸 배경에 선발 11명이 앉아 있고 주장이 앞에 선다.
- 주장 선정: **첫 시즌 규칙**(별 최고, 동률이면 나이 많은 선수). 임명 없음(튜토리얼 안).
- 대사(beats): 주장 → 감독 호칭은 첫 시즌 신뢰 단계(의심: "감독"): "감독님, 전반기 수고하셨습니다. 우리 선수단을 소개할게요." → 선수 소개 1줄(별 최고 선수·최고령 선수 등 2명, 이름 노출) → 올리비아 마무리 1줄 "이제 라커룸에서 한마디 해 주실 차례예요!".
- 소품: 선수 초상화(실제 선수), 주장 완장.

### 2.3 튜토리얼 토크 (ⓑ)
- 시점 형식은 ③(후반기 직전) 장면을 재사용. 캡션 "전반기가 끝난 라커룸 · {순위}위 · 승점 N".
- 풀: 6절 ③ 풀 7장 중 **고정 3장**(격려·영상 분석·농담 — 모두 안전 토크, 효과 작음). 튜토리얼 결과 카드에 "튜토리얼에서는 적용되지 않아요" 한 줄.
- 성격 반응: 장면에서는 몸짓 반응(성격 라벨 없음, 디자인), 수치는 샌드박스에만 적용되고 폐기.
- 주장 한마디: 기존 톤별 + 성격별 한 줄.
- 끝: 토크 확인 후 "튜토리얼이 끝났어요. 이제 진짜 구단을 만들어 볼까요?" → 구단 만들기.

### 2.4 튜토리얼이 흡수할 설명(3절과 연결)
튜토리얼 범위를 아래까지 넓힌다(기존 0~15 + 신규):
| 신규·확장 단계 | 흡수하는 설명 |
|---|---|
| 협상(탐색 3종·예상 이적료·인내심) 한 번 해 보기 | 현재 `introTick`의 `haggle` 안내 |
| 판매 등록 한 번 해 보기 + 판매 중 구역 | 현재 `introTick`의 `sale` 안내, 판매 중 선수 규칙(1절) |
| 특수 성향 칩 | 현재 `introTick`의 `traits` 안내 |
| 감독·스태프 탭 | 현재 `introTick`의 `staff` 안내(이미 단계 8~9에 일부 있음) |
| 스태프 리포트(성장폭·작년 흐름·부상 이력·차등 항목) | 신규 |
| 결산 ▲/▼ | 단계 15(스카우터 재평가) 확장 |
| 정원 N/22 | 선수단 탭 단계 확장 |
| 라커룸 토크·주장 | 신규(ⓐⓑ) |

### 2.5 수정 파일
`ui/app.mjs`(`tutorialTick`, `tutSet`, `introTick` 삭제, `startRun` 샌드박스 분기, 튜토리얼 종료 → `renderClubButtons`/구단 만들기, `showDialogueScene`에 `squad` 종류, `showTalkPick`에 튜토리얼 고정 3장 모드, `startTalkThen`·`endTalkThen` 조건), `ui/tutorial.mjs`, `data/flags.mjs`(`tutorialDone` 흐름), `ui/style.css`(D: 선수단 인사 장면).

### 2.6 테스트 기준
- 신규 유저 흐름: 시작 → 튜토리얼 → 전반기 결산 → 선수단 인사 → 토크 → "튜토리얼 끝" → 구단 만들기 → 본 게임이 1주차부터 새로 시작(7절).
- 튜토리얼 중 업적·records(런 수, 최고 점수)가 변하지 않는다.
- 튜토리얼을 건너뛰어도(`tutSkip`) 같은 끝 처리.
- 1시즌 본 게임에서 ①④ 토크가 뜬다(정식 임명 전이어도).

### 3.2 정리 규칙
- 시즌 중(튜토리얼 종료 후)에는 **스포트라이트(`showSpot`)를 다시 쓰지 않는다.** `introTick`과 호출부(`tutStep() < 0`일 때의 `introTick()`)를 삭제.
- 새 기능이 추가되면 설명은 튜토리얼에 넣는다(시즌 중 "처음 본" 팝업 금지).

## 5. 철학 선택 (사용자 확정, 시뮬 불필요)

### 5.1 규칙
| 항목 | 규칙 |
|---|---|
| 임명 때 선택지 | 정식 임명(첫 시즌 잔류)에서 **8종 전체**에서 1개 선택(현행: 무작위 3종). 태그형 6종은 카드에 "내 선수단 해당 태그 N명"을 표시, 토탈 축구·철벽 수비는 상시 효과 표시 |

| 변경 시 레벨 | 새 철학 Lv = `max(1, 현재 Lv − 2)` |
| 변경 제한 | 승격 때만(시즌당 최대 1회). 임명 이후 시즌 중 변경 불가 |
| 해금 조건 | 없음(처음부터 8종) |
| 최대 레벨 | 5(현행) |
| 정보 | 철학 카드: 이름·대사·효과 요약·필요 태그, 변경 화면에서는 "바꾸면 Lv N로 시작해요"를 한 줄로 알림 |

### 5.2 수정 파일
`ui/app.mjs`(`showPhilosophyPick`: `drawPhilosophyChoices()` 대신 `PHILOSOPHY_IDS` 전부, `showPhilosophyLevelUp`: 유지/변경 선택 추가), `engine/specialties.mjs`(`drawPhilosophyChoices`는 남겨 두되 호출 제거 가능, 변경용 레벨 계산 함수 `switchPhilosophy(ph, newId)` 추가), `ui/style.css`(D: 8장 카드 목록·변경 화면을 깔끔하게), `tools/sim-v3.mjs`(봇의 `choosePhilosophy`가 8종 전체에서 고르게 — 사용자가 시뮬 불필요라고 했으므로 선택).

### 5.3 테스트 기준
- 임명 화면에 8장이 모두 보이고 태그 수가 올바르다.
- 승격 모달에서 유지하면 Lv+1, 바꾸면 새 철학 `max(1, Lv−2)`.
- 저장→불러오기 후 철학 id·레벨이 유지된다.
- 이전 세이브(철학 있음)가 그대로 열린다.
