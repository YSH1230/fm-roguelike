# 튜토리얼 재설계 명세: 스크립트형 별도 흐름 (2026-10-15)

상태: 사용자 확정 피드백 반영, **구현 전**. 프로그래밍(P)·디자인(D) 세션이 그대로 따르는 명세다.
이 문서는 `docs/playfeedback-2026-10-14.md` §2·§10(튜토리얼)을 **대체**한다(§3 설명 팝업 정리·§7 격리 표의 확정은 유지).
**2026-10-15 사용자 확정: 라커룸 토크와 튜토리얼 끝의 선수단 인사 장면은 삭제.** 튜토리얼의 끝은 "종료 안내 → 구단 만들기"다(아래 반영).
표기: **[확정]** 사용자 확정, **[기본값]** 기획 제안(조정 가능). 함수·상수 이름으로 찾는다(행 번호 없음).

---

## 0. 목표와 원칙
- **[확정]** 튜토리얼 중의 모든 행동은 본 게임에 영향을 주지 않는다.
- **[확정]** 사용자가 읽고 누르는 대로 **정해진 순서(스크립트)**로 진행한다. 본 게임의 주차 진행·시장 난수·결산 시뮬에 의존하지 않는다.
- 고정 선수단·고정 영입 카드·고정 오퍼·고정 결과 화면으로 시스템을 하나씩 체험한다.
- 한 단계 = 한 가지 행동 + 한 가지 메시지(문장 1~2개, 행동 지시 먼저, 올리비아 말투).
- 시즌 중(튜토리얼 종료 후) 설명 팝업은 다시 나오지 않는다(`playfeedback` §3 유지).
- 종료 후 **구단 만들기부터 새 본 게임**을 시작한다.

## 1. 현재 구조의 문제 5가지와 분리 방법 (프로그래밍 세션 조사 반영)

| # | 현재 문제 | 분리 방법(이 명세에서의 규칙) |
|---|---|---|
| ① | 튜토리얼은 별도 상태가 아니라 **첫 본 게임 런**(`startRun` → `currentState`) 위에서 같은 함수를 쓰고 `tutStep() >= 0`로 분기한다 | 튜토리얼은 `startRun`을 **부르지 않는다.** `buildTutorialState()`가 만든 고정 객체를 `currentState`에 넣고 **구단 만들기보다 먼저** 시작한다(2절). 종료 시 `currentState = null`(본 게임 상태가 애초에 없음) |
| ② | `nextWeek`가 실제 주차 진행(조직력·판매 오퍼 만료·시장 부상·새 영입 카드·스태프 후보)을 하고, 시장 마감은 `showSeasonPreview → runFirstHalf`(진짜 반기 시뮬: 승점·평점·MVP·순위표·별 갱신·긴급 유스 콜업)까지 돈다. `ensureUpgradeOffer`가 카드를 최대 40번 다시 굴린다 | **가짜 주차 전환**: 튜토리얼이면 `nextWeek`·`runFirstHalf`·`runSecondHalfAndFinish`·`ensureUpgradeOffer`·`newShopOffer`·`rollMarketInjuries`·`rollSaleOffers`·`resolveListedSales`를 **호출하지 않고** 스크립트 함수(`tutorialHooks`)가 고정 상태로 교체한다(4절) |
| ③ | 영입·판매·방출·배치·북마크·스카우트 지시·스태프 고용이 모두 실제 `currentState`를 바꾼다 | 튜토리얼 `currentState`는 본 게임과 **완전히 다른 객체**라 바뀌어도 본 게임에 닿지 않는다. 그리고 허용 동작만 열어 둔다(스포트라이트가 지정한 곳만 클릭 가능). 스태프 고용·방출 등 비허용 동작은 막는다(5절) |
| ④ | 세이브·기록은 `tutorialBackup` 플래그로만 막는다(구단 이름·엠블럼 단계에서는 세이브가 쓰일 틈이 있다). flags(`tutorialStep`/`tutorialDone`/`markSeen`)는 계정 단위 | 튜토리얼은 **구단 만들기 이전**에 시작하므로 구단 이름·엠블럼 단계가 튜토리얼과 겹치지 않는다. `currentState.tutorial === true`인 동안 `saveRun`·`persistRun`·`updateRecords`·`recordRunStart/End`·`markSeen`을 **호출 경로에서 막는다**(함수 첫 줄에서 반환). flags에는 `tutorialDone`만 쓴다(단계는 저장하지 않음) |
| ⑤ | 선수 id 카운터(`nextId`)는 종료 때만 초기화된다 | 튜토리얼 선수는 **고정 id**(`t01`…`t16`, 카드는 `tc1`…`tc3`)를 쓰고 `nextId`를 올리지 않는다. GOD 풀·구단 기분 맵 등 전역 카운터는 건드리지 않는다. 종료 시 `resetPlayerIds()`는 호출해도 무해(검증용 안전장치) |
| 추가 | 단계 트리거가 화면 상태에 의존한다(탭 클릭이 `tutSet`을 올리고 "다음 주로" 클릭이 `tutSet(13)`) | **단계 트리거는 화면 상태가 아니라 스크립트 이벤트**다(3절 이벤트 표). 탭 이동은 스크립트가 직접 한다 |

## 2. 구조 (방식 B: 고정 상태 + 기존 화면 재사용 + 가로채기)

### 2.1 새 모듈 `ui/tutorial-script.mjs`
| 내용 | 설명 |
|---|---|
| `buildTutorialState()` | 난수 없는 고정 상태 객체를 돌려준다(본 게임 `currentState`와 같은 모양이라 기존 렌더 코드를 그대로 쓴다). `tutorial: true`, `week`, `phase`, `funds`, `chemistry`, `squad`(고정 16명), `shopOffer`(빈 배열), `listedForSale`(빈 배열), `club`(고정 구단), 리그 `tier5` |
| `TUTORIAL_FIXTURES` | 고정 선수단·영입 카드·판매 오퍼·협상 하한선·전반기 결과·▲/▼ 목록·시즌 전망(4절) |
| `TUTORIAL_STEPS` | 단계 표: `{ id, tab, selector, text, trigger, allow, onEnter }`(3절) |
| `tutorialHooks` | `nextWeek()`, `shopOffer()`, `saleOffers(card)`, `haggle(card)`, `firstHalf()`, `finish(skipped)` |
| `startTutorial()` | 상태 생성 → 선택한 첫 화면 렌더 → 단계 1 시작 |

### 2.2 본 게임 코드 변경(분기 지점은 아래 8곳만)
| 지점 | 변경 |
|---|---|
| 시작 화면 흐름 | 처음 실행(`tutorialDone` 아님)이면 구단 만들기 **앞에** `startTutorial()`. 다시 하고 싶으면 타이틀의 "튜토리얼 다시 보기"(선택) |
| `nextWeek` | `if (currentState.tutorial) return tutorialHooks.nextWeek()` |
| `showSeasonPreview` / 시장 마감 흐름 | 튜토리얼이면 고정 기자 3명 연출 후 `tutorialHooks.firstHalf()` |
| 영입 카드 생성(`newShopOffer`, `ensureUpgradeOffer`, `generateScoutDelivery` 호출부) | 튜토리얼이면 `TUTORIAL_FIXTURES.cards` 반환 |
| 판매 오퍼(`rollSaleOffers`) | 튜토리얼이면 `TUTORIAL_FIXTURES.offers` 반환 |
| 협상(`openHaggle`의 `reserve`·인내심 계산) | 튜토리얼이면 고정 하한선·인내심. 탐색·제안·응답 로직 자체는 그대로(고정 카드는 해시 기반이라 결과가 항상 같다) |
| 저장·기록(`saveRun`·`persistRun`·`updateRecords`·`markSeen`) | `currentState?.tutorial`이면 즉시 반환 |
- 위 외에 본 게임 함수에 튜토리얼 분기를 **추가하지 않는다.**

## 3. 단계 트리거 (스크립트 이벤트)
단계는 화면 상태가 아니라 **이벤트**로 넘어간다. 화면 코드는 해당 동작이 일어날 때 `tutorialEvent(name)`을 부르기만 한다(튜토리얼이 아니면 아무 일도 없음).

| 이벤트 | 발생 지점 |
|---|---|
| `scoutOrderPicked` | 스카우트 지시 select에서 조건 하나를 고름 |
| `cardOpened` | 영입 카드 펼침 |
| `explored` | 협상의 탐색 버튼 |
| `bidSent` | 제안 버튼(수락됨) |
| `formationPicked` | 포메이션 칩 |
| `marked` | ☆ 버튼(★ → ✂ 두 번 눌렀을 때 완료) |
| `listed` | 판매 등록 확인 |
| `counterSent` | 판매 협상의 [더 불러 보기] |
| `offerAccepted` | 판매 오퍼 수락 |
| `nextWeekPressed` | "다음 주로" |
| `confirm` | 스포트라이트의 [확인] |
| `skip` | [건너뛰기] |
- 탭 이동·화면 전환·카드 도착·결과 화면은 단계의 `onEnter`가 직접 한다(사용자에게 탭을 누르라고 시키지 않는다).

## 4. 고정 시나리오 데이터 (`TUTORIAL_FIXTURES`)

### 4.1 구단·상태
| 항목 | 값 |
|---|---|
| 구단 | 고정 구단 "FM 유나이티드"(고정 엠블럼·팀 색), 5부 |
| 시작 | 시즌 1, 여름 시장 1주차, 자금 120G, 조직력 60 |
| 목표 | 고정 목표 승점(5부 기준 표시값) |
| 스태프 | 코치·스카우터 모두 프로(리포트 2차등 항목이 보이게), 감독 임시 |
| 난수 | 튜토리얼 중 `Math.random` 호출 금지(8절 테스트) |

### 4.2 선수단 16명(선발 11 + 벤치 5, 예비 없음)
- 포지션은 기본 포메이션 슬롯에 맞춘 고정 배치. 이름은 기존 이름 풀에서 **고정**으로 고른다. 별(눈금 6)·태그·성격·부상 이력·리포트 값을 모두 고정.
- 요구되는 시연 요소:
| 요소 | 고정 선수 |
|---|---|
| 별 3.0~3.5가 다수, 최고 ★4.0 한 명(주장 후보: 첫 시즌 규칙 별 최고, 동률 나이 많은 순) | 선발 |
| 특수 성향 칩 1개 | 선발 1명(리포트 줄 한 줄로 설명) |
| 부상 이력 칩("지난 시즌 반기 아웃" 등) | 선발 1명 |
| 판매 연습용(벤치 FW, 별 2.0, 31세) | `t14` |
| 성격 | 4종이 각각 1명씩 이상 포함(화면에는 표기하지 않음) |
| ☆ 연습용 | 벤치 유망 선수 1명(성장폭 ↗) |

### 4.3 영입 카드 3장(지시 직후 즉시 도착, 3단계)
| 카드 | 용도 | 고정값 |
|---|---|---|
| `tc1` | 협상 연습(CB 업그레이드) | 요구액 40G, 구단 태도 "보통", 하한선 34G, 별 3.5, 리포트 항목 전부 표시 |
| `tc2` | 비교용(별 3.0) | 협상 대상 아님(스포트라이트가 `tc1`만 허용) |
| `tc3` | 비교용(별 2.5, 성장폭 ↗) | 협상 대상 아님 |

### 4.4 협상 고정 규칙(`tc1`)
- 인내심 3(소모 없음), 첫 탐색 무료, 탐색 결과는 고정(1회 후 "예상 이적료 32~38G").
- 제안 ≥ 34G → 수락, < 34G → "조금만 더 올려 주세요"(인내심·결렬 없음, 다시 제안 가능).
- 영입 완료 시 자금 −제안액(120G → 80G), 조직력 60 → 58(거래 벌칙), 선수단에 `tc1` 추가, 결과 팝업은 기존 영입 결과 화면 재사용. 이어서 6단계(자금·조직력 설명).

### 4.5 판매 고정 오퍼(`t14`)
| 오퍼 | 구단 | 금액 | 기한 |
|---|---|---|---|
| 1 | 고정 구단 A | 12G | 3주 남음 |
| 2 | 고정 구단 B | 15G | 이번 주까지 |
- 판매 협상: 오퍼 1(12G)은 [더 불러 보기]로 **16G까지 수락**, 그 위는 "조금만 낮춰 주세요"(인내심·결렬 없음). 어느 오퍼든 수락 가능(수락 시 자금 +금액, 선수 제거). 판매 중 규칙(선발·벤치 제외, 판매 중 구역)은 본 게임과 같은 렌더를 쓴다.

## 5. 입력 막기
- 스포트라이트(`showSpot`) 오버레이를 **항상** 띄운다(대상이 없는 구간은 투명 막). 허용 대상만 클릭이 통과한다.
- 허용 목록은 단계 표의 `allow` 셀렉터. 목록 밖 클릭은 무시(토스트 없음).
- 비허용: 스태프 고용·교체, 방출, 선수 교체, 이적 필터, 철학, 저장·불러오기, 구단 편집.
- [건너뛰기]는 항상 허용.

## 6. 단계 표 (사용자 순서 + 자금·조직력 단계, 16단계 + 종료 안내, 2026-10-16 갱신)

순서: 목표 → 스카우터 지시 → 선수 도착 → 리포트 → 영입 협상 → **자금·조직력** → 포메이션 → 선수단 정원 → 유망·정리 설정 → 판매 → 판매 협상 → 스태프(등급별 이점) → 다음 주로 유도 → 전·후반기 결산 → 별점 → 명성.
- **선수 도착은 지시 직후 즉시**(튜토리얼에서는 "다음 주"를 기다리지 않는다). "다음 주로"는 13단계에서 시즌 전체를 한 번에 넘기는 **가짜 전환**이다(겨울 시장·후반기 시뮬은 건너뛰고 고정 결과 화면으로).

- 6단계 고정값: 영입 후 자금 120G → 80G(협상 제안액 40G 기준), 조직력 60 → 58(거래 벌칙). 영입 결과를 이미 본 뒤라 새 화면 이동 없이 헤더만 강조.

- 12단계 등급별 이점 고정 표시(문구는 7절): 스카우터 = 지시 칸·좋은 카드·리포트 항목 수, 코치 = 성장 보너스·거래 조직력 벌칙 감소·내 선수단 리포트.

## 10. 테스트 기준
- 튜토리얼 중 `Math.random`을 오류 스텁으로 바꿔도 끝까지 진행된다(호출 0회).
- 같은 클릭 순서를 100번 반복해도 모든 화면(카드·승점·순위·▲▼)이 같다.
- "다음 주로"를 눌러도 본 게임 `currentState`가 생성되지 않는다(튜토리얼 상태만 바뀜).
- 튜토리얼 전체 동안 `localStorage`의 런 세이브·records·업적·`flags.seen`이 변하지 않는다(`flags.tutorialDone`만 마지막에 바뀜).
- 튜토리얼 후 구단 만들기에서 시작한 본 게임은 1주차·새 선수단·새 id.
- 어느 단계에서든 [건너뛰기]가 구단 만들기로 이어진다.
- 새로고침 후 튜토리얼이 처음부터 시작한다.
- 비허용 영역을 눌러도 아무 일이 없다.
